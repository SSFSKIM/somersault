### Task 1: Raw-SGR passthrough seam (`Segment.preStyled` + `Line` branch)

The bold-count mechanism (spec Decision Log 2026-08-04) needs one primitive: a segment whose text is
a PRE-STYLED byte string that Ink must not restyle. F1 proved `<Text dimColor bold>` drops bold and
that chalk mangles raw SGR nested inside a styled `<Text>`; an UNSTYLED `<Text>` is the passthrough
candidate — this task pins that with a test before anything builds on it.

**Files:**
- Modify: `src/tui/render.ts` (the `Segment` type)
- Modify: `src/tui/Line.tsx`
- Test: `test/tui/sgr-passthrough.test.tsx`

**Interfaces:**
- Consumes: `Segment` (existing: `{text, color?, dim?, bold?, italic?}`).
- Produces: `Segment` gains optional `preStyled?: true`. `Line` renders a `preStyled` segment as
  `<Text>{seg.text}</Text>` with NO style props (no color, no dimColor, no bold, no wrap
  interference). Task 2 builds on exactly this.

- [ ] **Step 1: Write the failing pin test**

```tsx
// test/tui/sgr-passthrough.test.tsx
import React from "react";
import { render } from "ink-testing-library";
import { Line } from "../../src/tui/Line.js";

const DIM = "\x1b[2m", BOLD = "\x1b[1m", B_OFF = "\x1b[22m";

test("an unstyled Text preserves raw SGR bytes verbatim (the mechanism's load-bearing premise)", () => {
  const raw = `${DIM}Read ${BOLD}3${B_OFF} files${B_OFF}`;
  const { lastFrame } = render(<Line l={{ text: raw, segments: [{ text: raw, preStyled: true }] }} />);
  expect(lastFrame()).toContain(raw);           // byte-identical, chalk did not rewrite the nested closer
});

test("a preStyled segment coexists with ordinary styled siblings", () => {
  const raw = `${DIM}x${B_OFF}`;
  const { lastFrame } = render(<Line l={{ text: `● ${raw}`, segments: [
    { text: "● ", color: "green" }, { text: raw, preStyled: true },
  ] }} />);
  expect(lastFrame()).toContain(raw);
});
```

- [ ] **Step 4: Green + `npm run typecheck`.**

### Task 2: Byte-exact fold-row writer — the real bold count (LT2's remaining half)

Replace the fold row's clause segments with a writer that emits upstream's exact byte shape.
Upstream (bundle L428046) renders the whole clause run as ONE outer `<Text>` containing nested

the next SGR open is PLAIN. That artifact is the target, not a bug to fix (spec Decision Log
2026-08-04). Both forms' clause runs are DIM (the code reads `dimColor={!s}` but the golden proved
that polarity wrong for the active row — spec revision 2026-08-03); settled adds `#999999`.

  group-row tests will need their expectations updated — that is the point of the task)

  (`#999999` default), Task 1's `preStyled`.

  the pre-styled byte string for the clause run INCLUDING the joining `", "`s, EXCLUDING the leader
  glyph, the `…`, and the `(ctrl+o to expand)` hint (those remain ordinary segments exactly as
  today).

Byte grammar `composeFoldRun` must produce. IMPORTANT CALIBRATION: the tracked golden
(`harness/test/fixtures/upstream-frames/f1-tool-rendering/01-read-complete.ansi`) is a
**pyte-reconstructed screen dump** — full-reset-prefixed per-CELL attribute runs
(`\x1b[0;2m`… style), never byte-comparable to any writer's stream. What binds is the per-cell

outer dim), and both forms' clause runs dim (the spec's 2026-08-03 correction of R3.5's polarity).

suite's job at re-baseline time.

  `composeFoldRun(clauses, "active", { ellipsis: true })` appends it plain. Close with `\x1b[22m`.
