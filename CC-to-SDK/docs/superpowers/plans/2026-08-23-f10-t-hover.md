# F10 T-HOVER Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-execution to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal.** Make ccx's hover unit match canon's: one whole SDK message in the transcript (H1), and a real
hover/click target on the composer's suggestion popup (H2, parity row `CM33`). Along the way, delete the
transcript background-band swap that never had canon backing, and re-home it on the one chrome widget that
does own it.

**Architecture.** H1 adds one optional field — `RenderItem.ownerKey` — minted beside `id` by every producer
of a transcript `RenderItem`. There are **twenty** such sites in **three** files, not the fifteen in one file
v1 claimed (r2 §Spec-drift 2, re-audited): eighteen in `toolRenderer.tsx` (seventeen object literals plus
`reid`'s spread-overwrite), one in `streamingItems.ts` (the live in-flight tier) and one in `ChatApp.tsx`
(the queued-prompt tier). All three files feed `FullscreenViewport`'s four-tier concatenation
(`finalRows ⧺ pendingRows ⧺ streamRows ⧺ queuedRows`, `:295-300`), so all three reach `hitRowsOf` and all
three are hoverable today. The field is carried through `wrapItems` by the spreads that already carry
`foldAnchor`, projected onto a new **required** `HitRow.ownerKey`, and compared by `FullscreenViewport`'s
hover provider instead of `sourceId(item.id)`. No layout tree, no row spans, no change to `HitRow.itemKey`
(T-SELECT keys character offsets on it — see Interfaces). H2 adds a second, popup-local hit region:
`SuggestPopup` derives
`{ top, rows }` **forward** from `useDockTop()` (the hoisted palette is the dock's first child, so its first
painted row *is* `dockTop`) and publishes an imperative handle through a ref that `ChatApp`'s existing single
`useMouseSink` routes motion and press into, ahead of the transcript tap machine.

**Revisions.** **r2 (2026-08-23)** — amended after an adversarial plan review, all findings verified
against the tree before adoption. Four changes: (1) the **producer census is complete** — twenty sites
in three files, not fifteen in one, with owner semantics for the agent batch, the live streaming tier
and the queued tier, and the source-shape guard widened to all three files plus a real-viewport cell;
(2) the popup **arrow-clear fires on the recognized navigation action** (`EditorResult.suggestionNav`),
not on an index diff; (3) the **hover-cache tests get an injected transform seam** so the memo is
provable as a memo; (4) the plan aligns with the spec's new binding **Wave assembly** section —
`HitRow.ownerKey` lands REQUIRED with T-SELECT's fields absent on this branch, and the constructor
inventory is handed to the merge controller. Commit paths corrected to be repo-root-relative from
`harness/`. One review sub-claim did not reproduce and is recorded in Spec-drift 8 rather than adopted
as written.

**Tech Stack.** TypeScript (ESM, `.js` specifiers), React 18 + Ink 5.2.1, vitest +
`ink-testing-library`, `string-width`, tmux-driven pty cells (bash), no new runtime dependencies.

```ts
// src/tui/toolRenderer.tsx — the field. OPTIONAL at the type level and MANDATORY at every producer:
// `undefined` is "this item is its own hover unit", which is what a non-transcript caller (dialogs,
// the markdown renderer, PlanDialog) legitimately is. The producer matrix is what keeps the
// transcript's own producers off that default.
export type RenderItem =
  | { kind: "line"; id: string; ownerKey?: string; line: RenderLine; wrap?: "truncate-end"; foldAnchor?: string; expanded?: boolean }
  | { kind: "gutter-block"; id: string; ownerKey?: string; gutter: …; body: readonly RenderLine[]; gutterStyle?: …; foldAnchor?: string; expanded?: boolean };

// the seven owner minters, beside the id minters they mirror (`:480-494`). All seven live here, in the
// one file that already owns transcript identity, even though two of them are called from other modules
// (`streamingItems.ts`, `ChatApp.tsx`) — one home for the owner namespace is what keeps two producers from
// inventing colliding prefixes.
export const sdkOwnerKey   = (base: string): string => `sdk:${base}`;
export const localOwnerKey = (identity: string): string => `local:${identity}`;
export const toolOwnerKey  = (toolUseId: string, resultSequence?: number | "pending"): string =>
  resultSequence === undefined ? `tool:${toolUseId}` : `tool:${toolUseId}:${resultSequence}`;
export const groupOwnerKey = (memberIds: readonly string[]): string => `group:${memberIds.join(",")}`;
/** An agent BATCH's header row. The batch's identity is its membership, exactly as `agentBatchItemId`
 *  (`:494`) already decided; `form` is carried for the same reason the id part carries it — a pending copy
 *  and the published copy of one batch can both be on screen during the hand-off, and two hover units that
 *  compare equal would light both up. Its MEMBERS do not use this key — see the census table. */
export const agentBatchOwnerKey = (memberIds: readonly string[], form: "published" | "pending"): string =>
  form === "pending" ? `agents:${memberIds.join(",")}:pending` : `agents:${memberIds.join(",")}`;
/** The live streaming tier. `messageKey` is `LiveTurn.messageKey()` — the API message currently on the
 *  wire. NOT the settled item's key: the settled row is keyed on `entry.identity` (the SDK message uuid,
 *  `sdkEntryBase` `:508`) and the wire's `message.id` is a different id space, so hover does not survive
 *  the settle. It does not need to — see Spec-drift 10. */
export const streamOwnerKey = (messageKey: string): string => `stream:${messageKey}`;
/** One queued prompt. Index-keyed because `QueueEntry` (`queue.ts:64-70`) has no id and the existing item
 *  id is already `queued:<i>:<j>` — this is that id's first component, nothing new invented. */
export const queuedOwnerKey = (entryIndex: number): string => `queued:${entryIndex}`;
```

 *  INCLUSIVE terminal columns (an SGR report's own coordinates); `lines` is the row's painted height,
 *  1 or 2, straight off `rowLines` (canon `OSw`). Rows are in WINDOW order, so the index of a hit is
 *  `P` and the absolute suggestion index is `windowStart + P` (canon's `onSelect(I)`, L536295). */

/** `top` is the region's FIRST terminal row — `useDockTop()`, because the hoisted palette is the
 *  dock's first child (ChatApp.tsx:1783). `0` = not addressable, the same contract `RegionTopContext`
 *  and `DockTopContext` state (FullscreenFrame.tsx:126-141). */

/** The WINDOW-relative index of the row a cell lands on, derived FORWARD from `region.top` — each row

      export function popupHitRegion(windowItems, windowLineCounts, top, columns): PopupHitRegion {
        const colStart = PALETTE_PADDING_X + 1, colEnd = columns - PALETTE_PADDING_X;
        if (top <= 0 || colEnd < colStart) return { top: 0, rows: [] };
        return { top, rows: windowItems.map((it, i) => ({ id: it.id, colStart, colEnd, lines: windowLineCounts[i] ?? 1 })) };
      }
      export function popupRowAt(region, col, row): number | undefined {
        if (region.top <= 0) return undefined;
        let y = region.top;
        for (let i = 0; i < region.rows.length; i++) {
          const r = region.rows[i]!;
          if (row >= y && row < y + r.lines) return col >= r.colStart && col <= r.colEnd ? i : undefined;
          y += r.lines;
        }
        return undefined;
      }

```ts
/** Bounded memo over a pure string→string transform. The transform is a PARAMETER so a test can count
 *  its calls — "the same input transformed once" is the only assertion that distinguishes a memo from a
 *  plain function, and every assertion about the memo's *output* passes without one. Keyed on the raw
 *  string itself: a segment's bytes are stable across frames while the block is hovered, which is
 *  exactly the repeat this exists to collapse. Capped and cleared WHOLESALE at the cap — an LRU's
 *  bookkeeping would cost more than the replace it saves, and the working set is bounded by the
 *  window's row count. */
export function memoizeByInput(
  transform: (raw: string) => string, max: number,
): (raw: string) => string {
  const cache = new Map<string, string>();
  return (raw) => {
    const hit = cache.get(raw);
    if (hit !== undefined) return hit;
    const out = transform(raw);
    if (cache.size >= max) cache.clear();
    cache.set(raw, out);
    return out;
  };
}
const UNDIM_CACHE_MAX = 512;
const stripDim = memoizeByInput((raw) => raw.replace(DIM_SGR, ""), UNDIM_CACHE_MAX);
```

   - **`streamingItems.ts:28`** — the live in-flight tier. One `kind: "line"` item per `RenderLine`,
     id `stream:<i>`. Verified reachable: `FullscreenViewport` builds `streamRows` from it at `:298`
     and concatenates it into the same `items` array `pageItemSlices` → `hitRowsOf` walks (`:295-300`).
     Left alone, a live multi-line assistant message would keep one hover unit per LINE — exactly the
     defect H1 exists to remove, on the surface where the user is most likely to be pointing.
   - **`ChatApp.tsx:1397`** — the queued-prompt tier, id `queued:<i>:<j>`, same concatenation.

   Task 1 Step 3 enumerates all twenty with owner semantics; the source-shape guard (Step 1, cell (j))
   now scans all three files; cell (n) walks the real viewport, which is the only check that would
   have caught this class of omission rather than restating it.

3. **`lineCount` is called `rowLines`.** The spec cites `suggestPopup.tsx:150-161 lineCount` and
   `:172-182 scrollWindow`. The exports are `rowLines` (`:153`, canon `OSw`) and `scrollWindow`
   (`:173`, canon `DXe`). Both are pure and correct as the spec assumes; only the name and the line
   numbers differ.

4. **The popup's not-addressable condition is NOT `originExact`.** The spec says the region "degrades
   to not-addressable under exactly the conditions `originExact` does." Taken literally that is
   self-defeating: `originExact` is `fullscreen && dockTop > 0 && !dockCrowded && !hoisted`
   (`ChatComposer.tsx:1344`), and `hoisted` — the palette being up — is the popup's own precondition.
   Research §4.2 names this inversion ("the same fact that blocks the composer *is* the palette's own
   origin"). The plan implements the intent: **`fullscreen && dockTop > 0`**, no occupant term,
   because the palette is the dock's FIRST child (`ChatApp.tsx:1783`) and nothing paints above it.

5. **`dockTop` is one frame stale when the palette opens.** `DockTopContext`'s value is
   `REGION_TOP_ROW + regionRows` (`FullscreenFrame.tsx:337`) and `regionRows` is MEASURED
   post-layout by an effect, so the frame in which the palette first appears can publish the
   pre-shrink origin. The composer's caret origin already lives with exactly this. Consequence here
   is one hover tick resolving to nothing; the next motion report corrects it. The frame-output
   pinning cell must therefore settle frames before asserting (the suite's existing `settle()` idiom),
   and this is recorded rather than engineered around.

6. **The jump pill has no `HitRow`, by construction.** Re-homing the band swap needs a live hover
   source, and `FullscreenViewport` deliberately removes the pill's row from the window
   (`body = height - 1`, `:487`), so no hit row describes it. Rather than inject a synthetic row into
   an array T-SELECT indexes for selection, the plan adds a **pill-row arm to `hoverAt`** keyed on a
   published `pillRow`. Two consequences, both recorded: the target is the whole pill ROW where
   canon's `O6w` targets the badge box; and the pill is never part of a selection, which is correct
   and unchanged.

7. **The band swap's blast radius is wider than `Line.tsx`.** r2 §4.3 names the user-prompt echo
   (`render.ts:117-121`) and the fork-boilerplate species (`species.ts:317`) as the two producers
   that emit `userMessageBackground`. Removing `hoverBand` changes the painted output of both under
   the pointer. Task 1 Step 8 expects fallout in suites beyond `hover.test.tsx`; the rule is to
   invert those assertions, never to reinstate the swap.

8. **A REVIEW FINDING PARTLY DID NOT REPRODUCE: popup arrows at the list bounds.** The r2 review
   asked for an unconditional arrow-clear on two grounds — the one-item list, and "top/bottom bounds
   where an arrow is recognized but the index stays fixed." Only the first reproduces here. **Both
   ccx popups WRAP**: `moveSuggestion` is `(index + delta + length) % length`
   (`completions.ts:150-153`, a deliberate F5 correction of an earlier clamped version), so an arrow
   at either bound always moves the index and v1's diff would have cleared. The one-item list is the
   real hole — `(0 + 1 + 1) % 1 === 0`. **The recommendation is adopted anyway**, because clearing on
   the recognized action is both the approved semantic and the predicate that keeps working if any
   future list stops wrapping; the fix is `EditorResult.suggestionNav` (Task 2 Steps 8–9), not an
   index diff with a second exemption bolted on. Recorded so that a reader who checks the bounds
   claim against the tree finds this note instead of concluding the amendment was unnecessary.

9. **`QueueEntry` has no id, so the queued owner is index-keyed** (`queue.ts:64-70`). That is not a
   new weakness introduced by this plan: the queued item ids are already `queued:<i>:<j>`, so the
   owner is that id's first component and inherits exactly the same stability. Queue mutation
   re-indexes both together, and a hover that survives a drain resolves against the new frame's rows
   on the next motion report or is dropped by the stale-hover clear. Minting durable ids for queue
   entries is a real improvement and a different ticket.

10. **The live tier's owner cannot follow a message across its settle, and does not need to.** The
    streaming region is keyed on `LiveTurn.msgId` — the API `message.id` from `message_start` — while
    the settled row is keyed on `entry.identity`, the SDK message uuid (`sdkEntryBase`, `:508`). Two
    id spaces; no cheap bridge. It costs nothing, because the two never coexist: the complete
    assistant message's `ingest` clears `current` (`:135`) before the document publishes the settled
    item, so the streaming tier is empty for at least one frame in between and the stale-hover clear
    fires on its own. **Rejected alternative:** a single constant `"stream"` owner for the whole
    tier. Verified sufficient for the same reason (one message at a time, an empty frame between
    messages) and cheaper — no `messageKey()`, no `ChatState` field, no prop. Not taken because the
    spec's unit is *one message* and a constant makes the unit *the region*: the two agree today only
    because of an implementation detail in `LiveTurn` that nothing tests, and a key that names the
    message is the one that keeps agreeing if that detail changes.

11. **A memo without an injected transform is untestable as a memo.** v1's Task 3 Step 4 proposed a
    module-level `Map` inside `unDimRaw` and covered it with output assertions (same input twice
    returns the same string, collision correctness, correct answers after the cap). Every one of
    those stays green with the cache deleted, so the suite would not have stopped the measured cost
    returning — which is the only reason the memo would ship at all. `memoizeByInput(transform, max)`
    (Task 3 Interfaces) is the smallest change that makes "transformed once" observable, and its two
    call-count cells are the only cells in that step that a deleted or unbounded cache turns red.
