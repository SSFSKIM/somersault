# F9 T-AUTO Implementation Plan — interactive default permission mode `auto`

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The interactive REPL (foreground and `--detachable`) launches in `auto` when the effective model supports it, unifying every ccx surface on one default mode, with banner truth preserved and an explicit `--model` always winning.

**Architecture:** One new launch resolver in a leaf module consumed by both interactive constructors; the notice copy gains canon 2.1.236's two-variant selection keyed off the observable token source; the qa3-03 reversal is recorded in the QA triage doc and the stale EP-T1 comment rewritten.

**Tech Stack:** TypeScript ESM, vitest.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-22-f9-wave-design.md` (Track T-AUTO). Research: `.doperpowers/sdd/2026-08-22-f9-wave/r5-permission-auto.md`.

## Global Constraints

- An explicit `--model` **always** keeps its model. An explicit `--permission-mode` always keeps its mode. The defaulted case: alias-resolve the effective model (`resolveModelAlias`), then gate with the **predicate** `isAutoSupportedModel` (`src/config/autoModel.ts`) — never the transformer `resolveAutoModel`.
- Both interactive constructors change together (`src/cli/main.ts:440` and `src/cli/hostMain.ts:51`) or the EP-T1 split-brain defect returns. `needsBypassConsent` (`main.ts:330`) reads the same single rule.
- Headless `-p`, `--bg`, daemon, library, `ccx attach` semantics unchanged.
- Notice variant rule (recorded divergence): `tokenSource === "CLAUDE_CODE_OAUTH_TOKEN"` → copy **without** "Sessions are slightly more expensive."; otherwise the cost-sentence variant. Canon cite for the two variants: 2.1.236 L676952-676958.
- Commands from `CC-to-SDK/harness/`: `npm run typecheck`, `npx vitest run test/unit/cli-main.test.ts`, `npm run test:unit`. Never bare `npm test`. Commit per task, no `Co-Authored-By`, never push.

**Interfaces:**
- Produces: `resolveLaunchPermissionMode(args: { explicitMode?: PermissionMode; effectiveModel: string | undefined }): { mode: PermissionMode; explicit: boolean }` — `explicitMode` set ⇒ `{mode: explicitMode, explicit: true}`; else `{mode: isAutoSupportedModel(resolveModelAlias(effectiveModel ?? - Consumes: `resolveModelAlias` (existing model-alias helper — locate with `rg -n "resolveModelAlias" src/config`), `isAutoSupportedModel` from `src/config/autoModel.ts`.
- **`effectiveModel` is the same value the constructor already computes** (`inv.config.model ?? prefs.model` in `main.ts:420`) — the saved model preference participates, per spec.
- **Both constructors must see the same effective model (plan-review catch):** `hostMain.ts` loads no prefs, so a saved non-auto model would split foreground (`default`) from detachable (`auto`). Fix: materialize the effective model where the detachable child is spawned (forward it explicitly into the child's config), or have the interactive child load prefs identically — implementer's choice, but the test below pins the outcome: with a saved unsupported model and no `--model` flag, foreground AND `--detachable` both launch `default` with that model; with a saved alias of a supported model, both launch `auto`.

// test/unit/launchMode.test.ts
import { describe, it, expect } from "vitest";
import { resolveLaunchPermissionMode } from "../../src/cli/launchMode.js";

describe("resolveLaunchPermissionMode", () => {
  it("explicit mode always wins, even auto on an unsupported model", () => {
    expect(resolveLaunchPermissionMode({ explicitMode: "default", effectiveModel: "claude-opus-5" }))
      .toEqual({ mode: "default", explicit: true });
    expect(resolveLaunchPermissionMode({ explicitMode: "auto", effectiveModel: "claude-haiku-4-5-20251001" }))
      .toEqual({ mode: "auto", explicit: true });
  });
  it("defaulted: auto-capable model (incl. via alias) → auto", () => {
    expect(resolveLaunchPermissionMode({ effectiveModel: "claude-opus-5" }).mode).toBe("auto");
    expect(resolveLaunchPermissionMode({ effectiveModel: "opus" }).mode).toBe("auto");     // alias resolves FIRST
    expect(resolveLaunchPermissionMode({ effectiveModel: undefined }).mode).toBe("auto");  // DEFAULTS.model is auto-capable
  });
  it("defaulted: non-auto model → default, and never explicit", () => {
    const r = resolveLaunchPermissionMode({ effectiveModel: "claude-haiku-4-5-20251001" });
    expect(r).toEqual({ mode: "default", explicit: false });
  });
});
