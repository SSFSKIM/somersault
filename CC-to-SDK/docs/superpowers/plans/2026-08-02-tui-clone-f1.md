- Produces:

  ```ts
  export type TranscriptSource = "host" | "disk" | "local";
  export type SidecarAssociation =
    | { scope: "call"; value: unknown }
    | { scope: "message"; value: unknown; reason: "no-tool-result" | "missing-tool-use-id" | "unmatched-tool-use" | "ambiguous-tool-results" | "duplicate-tool-use" | "duplicate-tool-result" };
  import type { RenderLine } from "./render.js";
  export type LocalTranscriptEvent = {
    kind: "notice" | "user-echo" | "command-echo" | "resume-divider" | "rewind-divider" | "source-gap" | "decision-settled" | "visual";
    lines: readonly RenderLine[];
    data?: Record<string, unknown>;
  };
  export type TranscriptBootstrapEntry =
    | { kind: "sdk"; source: "disk"; message: Record<string, unknown> }
    | { kind: "local"; identity: string; event: LocalTranscriptEvent };
  export type TranscriptEntry =
    | { sequence: number; source: "host" | "disk"; kind: "sdk-message"; identity?: string; message: Record<string, unknown>; sidecar?: SidecarAssociation }
    | { sequence: number; source: "local"; kind: "local-event"; identity: string; event: LocalTranscriptEvent };
  export interface ToolEvent {
    id: string; name: string; input: unknown; callSequence: number;
    route: "top-level" | "nested"; parent_tool_use_id?: string;
    result?: { content: unknown; isError: boolean; resultSequence: number; sidecar?: SidecarAssociation };
  }
  export class TranscriptDocument {
    appendSdk(source: "host" | "disk", message: Record<string, unknown>): boolean;
    appendLocal(event: LocalTranscriptEvent, identity: string): boolean;
    appendFollowGap(identity: string): boolean;
    entries(): readonly TranscriptEntry[];
    toolEvents(): readonly ToolEvent[];
  }
  export type ToolStatus = "running" | "success" | "error" | "interrupted" | "rejected" | "suppressed";
  export interface NormalizedToolResult {
    tool: string; status: ToolStatus; source: "pending" | "structured" | "fallback";
    rawContent: unknown; flatText: string; summary: string; output: string; outputLines: readonly string[]; structured?: Record<string, unknown>;
  }
  export function normalizeToolResult(event: ToolEvent, options?: { verbose?: boolean }): NormalizedToolResult;
  ```

  Task 1 is renderer-independent: local records are `LocalTranscriptEvent`, never a future `RenderItem`, so its typecheck does not depend on Task 3. `RenderLine[]` is permitted only as the faithful payload of an inherently local visual event: it retains existing `/help`, `/usage`, `/status`, local Bash, welcome, notice, and error formatter output without a second ordered transcript or formatter rewrite. It is never the canonical reduction of an SDK message or tool result. `appendSdk` uses only a source-stable identity to deduplicate disk/follow repetition: user `uuid`, assistant `message.id`, or a tool-use ID tuple. If no such identity exists, append rather than structurally hashing payload text; two equal-looking calls can be distinct turns. This preserves truth rather than hiding a genuine repeated call. `appendFollowGap()` itself stores `{ kind: "source-gap", lines: [{ text: "Earlier live output unavailable while attaching", dim: true }] }`; callers supply only its stable identity, and Task 4 calls it only on a truncated follow-start event. `TranscriptBootstrapEntry[]` is the sole startup handoff: array order is the total SDK/local order, and every local envelope already carries the stable identity reused by projection. `appendLocal` deduplicates only by that identity, never by line payload; equal-looking events with different identities are distinct history.

  `TranscriptDocument` remains raw/source-only and never imports `RenderItem`, React, or projection types. `toolRenderer.tsx` imports the document/tool types and owns all three projections, so every caller has one renderer boundary. `initialLines`, `initialMessages`, and `initialLocalEvents` are removed from attach/bootstrap’s source handoff. `initialEntries` is one ordered, identity-bearing `TranscriptBootstrapEntry[]` stream: disk SDK messages are `{ kind: "sdk", source: "disk", message }`; every fallback/welcome/bootstrap notice is `{ kind: "local", identity, event }` and its event already carries rendered `RenderLine[]`. This retains order and prevents welcome, commands, notices, errors, and local Bash output from masquerading as persisted SDK rows or living in a second history. The append-only linearization rule is explicit: an open header is transient at `callSequence`; the immutable finalized header-plus-result unit is anchored at `resultSequence`, while local visual entries publish at their own sequence immediately. Thus a local command output that arrives between call and result enters Static first, then the finalized tool unit follows. `projectPending()` returns only open top-level tool calls, while `projectCompact()` returns final top-level tool units, `projectMessageEntry()` ordinary non-tool SDK blocks, and local visual entries in that publication order. Same-session rehydration preserves `staticItems` and `publishedItemIds`, so it appends only genuinely unseen source. A rewind, `/clear`, or actual session change must instead cross an explicit terminal boundary. `runChatClient()` creates `createDeferredClearBridge()` **before** `render()`, passes `bridge.clearStaticTranscript` through `ChatApp` to `useChat`, then binds `() => app.clear()` immediately after `render()` returns. The bridge coalesces any pre-bind requests into one pending clear and delegates every later request directly; never drop the request and never add this internal callback to public `ChatClientOpts`. `useChat` calls it before bumping a `staticEpoch` key and resetting the document, `staticItems`, and `publishedItemIds`. Never reset those state values into the already-mounted `<Static>` instance. Host follow has two distinct truncated branches. A `turn:start { truncated:true, seq:number }` is a live mid-turn replay: append `follow-gap:<seq>`, create the transient `LiveTurn`, and set busy. A bare `turn:start { truncated:true }` is the completed idle tail from `Host.follow()`: append one stable `follow-gap:idle:<document-epoch>:<follow-generation>` record, mark only an `idleFollowReplay` ingestion mode, append its following messages directly to the canonical document, and clear that mode on the replay-ending `state` frame; it must never create `LiveTurn`, set busy, or wait for a nonexistent `turn:end`. Compact and detail show the retained, explicit `Earlier live output unavailable while attaching` record rather than claiming either replay is complete.

  `projectMessageEntry()` is the sole non-tool completed-SDK adapter: it reuses `render.ts` only for assistant/user text blocks and existing non-tool message species, while skipping `tool_use` and `tool_result` blocks so tools retain the one renderer route. Its ordering anchor is the containing `TranscriptEntry.sequence`; local entries use their own sequence; a final tool header-plus-gutter unit uses `resultSequence`. The id builders are deterministic: `sdkEntryBase()` returns the entry's source identity when it has one, otherwise `<stable-canonical-message-hash>:<occurrence-in-document-order>` — that hash fallback is **only for projection identity, never for append/dedup**, because `appendSdk` deliberately refuses to hash payloads (Task 1). `projectLocalEvent()` maps **every** `event.lines[index]` to `{ kind: "line", id: localItemId(entry.identity, index), line }` without adding a second style rule; the local event already owns its exact `RenderLine` styling. Thus `appendFollowGap()` projects its supplied dim line in both compact and detail. So: `local:<local-identity>:line:<line-index>` for those preformatted local lines, `sdkItemId(sdkEntryBase(entry, occurrence), "block:<content-index>")` for ordinary message blocks, and `toolItemId(id, resultSequence, "header" | "body")` for finalized units (`toolItemId(id, "pending", …)` remains transient and is never published). This gives `publishedItemIds` stable values across same-session rehydration without collapsing two equal-looking source records.
