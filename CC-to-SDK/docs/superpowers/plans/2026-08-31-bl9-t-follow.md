# bl9 T-FOLLOW Implementation Plan (v2) — post-follow attach reconcile

> **For agentic workers:** REQUIRED SUB-SKILL: doperpowers:subagent-driven-development, task-by-task.
> Steps use checkbox (`- [ ]`) syntax.
> v2 REPLACES v1 wholesale after the adversarial plan review (spec §3's v2 note): NO wire change,
> NO host change, NO fleetEngine change. The fix is a one-shot client-side reconcile.

**Goal:** A client that attaches (or resumes) after an in-place rewind no longer renders the
pre-truncation transcript forever: after the follow ack, `useChat` re-reads the transcript once
and rebuilds only if disk changed since the pre-follow read.

**Architecture:** `prepareAttach` returns a disk **stamp** (`{ lastUuid, count }`) beside its
bootstrap entries; the stamp threads through `runChatClient` opts into `useChat`, which runs a
one-shot reconcile after the session's `whenReady()`: re-read via the existing
`deps.getSessionMessages` seam, compare stamps, and on mismatch run a **narrow rebuild** (document
only — never the task panel, bg-harvest, or prefill). The refuted `decision_settled` half is
pinned by a guard test; fake-host's over-generous pre-follow drain is narrowed red-first via an
extracted policy module.

**Tech stack:** TypeScript ESM (`.js` specifiers), vitest, ink-testing-library harnesses, DI fakes.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-31-bl9-followreplay-polish-design.md`
(§3 v2, D14-D16, A1-A5, A8). Research: `.doperpowers/sdd/2026-08-31-bl9-round/research-follow-replay.md`
(R1) and `planreview-findings.md` (the two highs this design dissolves).

  prefill (spec D16 — review F2's loss scenario). Do not reuse `rebuildAfterRewind` whole;
  extract its document core.

  by ONE exported helper used by both `prepareAttach` and the reconcile (no second
  implementation to drift).

```ts
// bl9 D14: the attach staleness window is the client's own read-disk-before-follow interval
// (attach.ts reads, then the Ink import + mount + connect + follow land hundreds of ms later).
// One post-follow re-read closes it: match → no-op, mismatch → document-only rebuild (D16 —
// the follow drain's tasks/turn frames are live truth this reconcile must not clear).
useEffect(() => {
  const stamp = opts.initialDiskStamp; const ready = (session as { whenReady?: () => Promise<void> }).whenReady;
  if (!stamp || typeof ready !== "function") return;
  let cancelled = false;
  void ready.call(session).then(async () => {
    if (cancelled || disposed.current) return;
    const id = session.sessionId; if (!id) return;
    const rows = await getSessionMessages(id).catch(() => null); if (cancelled || rows === null) return;
    const fresh = diskStampOf(rows);
    if (fresh.count === stamp.count && fresh.lastUuid === stamp.lastUuid) return;
    replaceFromDisk(rows, id);
  });
  return () => { cancelled = true; };
}, []);
```

  (Adapt names/refs to the file's idiom; the effect body is the contract. `replaceFromDisk`
  updates the stamp ref so a later live `rewound` rebuild composes.)
