# F9 T-MOUSE Implementation Plan — the fullscreen mouse remainder

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fullscreen ccx arms canon's full tracking set and ships hover brighten, drag selection with auto-copy (native + OSC 52), and click-to-caret — all as queries against a widened hit map, since ccx has no layout tree or cell buffer.

**Architecture:** Six tasks in strict order: (1) the hit-map substrate, (2) arming + decoding, (3) hover, (4) click-to-caret, (5) the selection engine, (6) auto-copy + the clipboard rewrite. New leaf modules for selection state (`src/tui/mouse/selection.ts`) and clipboard channels (`copy.ts` rewrite); paint integration in `FullscreenViewport`/`FullscreenFrame`.

**Tech Stack:** TypeScript ESM, Ink (stock — no fork), vitest; raw SGR mouse byte fixtures.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-22-f9-wave-design.md` (Track T-MOUSE). Research: `.doperpowers/sdd/2026-08-22-f9-wave/r1-mouse.md` — read §1 (ccx today) and the §3 gap tables before starting any task; every canon cite below is expanded there.

## Global Constraints

- **Coordinates are 1-based end-to-end** (spec v2 decision). `top <= 0` stays the not-addressable sentinel. Do NOT convert to 0-based anywhere.
- The mouse event type is a **discriminated union**: `motion` has no `button` field; `press`/`release`/`drag` carry `button: 0|1|2`. Existing press/release semantics and every existing test stay green unmodified (except where a test names the widened type).
- Dispatch gate: `off` drops all mouse events; `scroll` drops left-button press/release and all motion/drag. Wheel behaviour unchanged in all modes.
- Mode selector: default `"full"` = `\x1b[?1000h\x1b[?1002h\x1b[?1003h\x1b[?1006h`; env `CLAUDE_CODE_DISABLE_MOUSE` → `off`, `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` → `scroll` (canon `G_e()` L126009). `MOUSE_OFF` teardown string unchanged. Arming still rides the alt-screen enter string — no new independent write sites, no new signal handlers.
- Word-select char class verbatim: `/[\p{L}\p{N}_/.\-+~\\]/u` (canon `tfS` L198741). Multi-click window: 500 ms, 1 cell both axes.
- `copyOnSelect` setting default **true**. Copy is always plain text.
- All new behaviour dead under `scroll`/`off` (acceptance 7).
- Grapheme/wide-cell correctness is required, not optional: CJK, emoji, combining marks test cells in the substrate task.
- Commands from `CC-to-SDK/harness/`. Never bare `npm test`. Commit per task, no `Co-Authored-By`, never push.

```ts
// src/tui/mouse/hitmap.ts
export interface HitRow {
  itemKey: string;            // stable identity of the source item (slice index is NOT stable across
                              // repaints of the same frame? it is within one publish — use the item's
                              // own id where RenderItem has one, else `i:<sliceIndex>` of the publish;
                              // hover only ever compares keys within one frame, so per-publish stability suffices)
  anchor?: string;            // foldAnchor, exactly today's click-to-expand channel
  width: number;              // painted extent, stringWidth-measured (unchanged)
  text: string;               // PLAIN text of the painted row (stripSgr'd at publish)
  gutterWidth: number;        // columns before text starts (0 for plain lines)
  softWrap: "hard" | "continuation";  // does this row start a logical line or continue the previous
  kind: "line" | "gutter-block";
  linkRanges?: readonly { start: number; end: number; href: string }[]; // plain-text offsets, where fold data has them
}
export interface CellAddress { row: number; charStart: number; charEnd: number } // grapheme-snapped
/** Map a 1-based terminal column to grapheme bounds in row.text (accounting for gutterWidth and
 *  double-width cells; column on the trailing half of a wide char snaps back — canon's backstep). */
export function columnToChar(row: HitRow, col: number): CellAddress | undefined;
export function charToColumn(row: HitRow, charIndex: number): number;
```

- `hitRowsOf` publishes the widened rows from the same slices being painted (map ≡ paint invariant). Plain text via the existing `stripSgr` (from `sgrFoldRow.ts` — it already strips OSC-8 too). `wrapItems.ts` exposes the continuation flag it already computes internally. `columnToChar` reuses the X4T grapheme snapper (`snapToGraphemes` in `suggestPopup.tsx` — extract it to a shared leaf if needed) + a `stringWidth` walk.
