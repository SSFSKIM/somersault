# F9 T-IMAGE Implementation Plan — image paste (Ctrl-V) — v2

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ctrl-V pastes a clipboard image as an `[Image #N]` chip that submits — through the REAL REPL path (loopback socket) — as a base64 image content block the model demonstrably reads; image blocks render as `[Image #N]` rows on every transcript surface.

**Architecture (v2 — matches spec v3):** every REPL client submits over the host socket (`chatMain.tsx:713` → `remoteChatSession`), so image bytes cross by **file handoff**: the client writes bytes into the fleet root, the `prompt` op carries a small manifest, the host validates/assembles/deletes. Authoritative limit enforcement lives in the Session message builder. Task order: I4 projection (standalone) → clipboard reader → composer entry → the input union + builder → the handoff transport → live verification.

**Tech Stack:** TypeScript ESM, vitest; `osascript`/`sips` (darwin); probe-113-verified wire shape.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-22-f9-wave-design.md` v3 (Track T-IMAGE). Research: `.doperpowers/sdd/2026-08-22-f9-wave/r4-image-paste.md`.

## Global Constraints

- Wire shape exactly `{type:"image", source:{type:"base64", media_type, data}}`; assembly text block first, images appended.
- Limits: 2000×2000 px, 5 MiB base64 input, 512,000-byte post-processing per-block ceiling, 5 MiB aggregate per turn. **Once a chip exists, a limit/processing failure NEVER drops or blocks the turn — it becomes the text block `[Image could not be processed: <reason>]` and the turn submits.** Paste-time "no image on clipboard" is the only path that inserts nothing (toast).
- Image payloads never land in `history.jsonl` or the on-disk paste cache (`pasteCache.ts` via `promptHistory.ts`); volatile in-memory state (stash/undo/queue `pastedContents`) KEEPS image entries; the SDK's own transcript persistence is untouched.
- Every boundary is tested at its exact limit value (1999/2000/2001-px style cells, 512,000±1 bytes, aggregate at 5 MiB ± one block).
- Public API: new types exported from `src/index.ts`; `npm run build` must pass (declaration emit).
- SECURITY: never print/echo/log the OAuth token or API key; live cells load env via `set -a; . ../.env; set +a`.
- Commands from `CC-to-SDK/harness/`. Never bare `npm test`. Commit per task, no `Co-Authored-By`, never push.

```ts
export type ClipboardImageResult =
  | { kind: "image"; data: Buffer; mediaType: string; dimensions: { width: number; height: number } }

export function readClipboardImage(deps?): Promise<ClipboardImageResult>;
export function pngDimensions(buf: Buffer): { width: number; height: number } | null;   // IHDR bytes 16-24

/** darwin ladder: sips resample to fit 2000×2000, then JPEG q 80/60/40/20 until ≤ 512_000 bytes.
 *  Returns the PROCESSED result — bytes, the RESULTING mediaType (image/jpeg after re-encode,
 *  original when passthrough), and re-measured dimensions — or null when still over budget. */
export function reencodeDarwin(input: { path: string; mediaType: string }, deps?):

The ladder runs **at paste time** (client side), so the entry's dims/type are the processed truth.
