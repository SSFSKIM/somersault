# F9 T-IMAGE Implementation Plan — image paste (Ctrl-V) — v3

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ctrl-V pastes a clipboard image as an `[Image #N]` chip that submits — through the real REPL socket path, on all three clients (loopback, detachable, attach) — as a base64 image content block the model demonstrably reads; image blocks render as `[Image #N]` rows on every transcript surface.

**Architecture (v3, matches spec v3.1):** the editor stops flattening chips (a structural `ComposerSubmission` rides editor → ChatComposer → ChatApp → useChat → queue); the socket-owning adapter stages bytes via a new negotiated `stageImage` host op (old hosts reject it loudly — no silent loss through Zod's unknown-key strip); the host reserves the turn sequence synchronously, assembles blocks, deletes claimed files in `finally`, and sweeps orphans; the Session message builder is the authoritative normalizer (it decodes image headers itself). Non-REPL surfaces (harness.run/stream, app-server, daemon, fleet) stay string-typed this wave — recorded follow-up.

**Tech Stack:** TypeScript ESM, vitest; `osascript`/`sips` (darwin); probe-113-verified wire shape.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-22-f9-wave-design.md` v3.1 (Track T-IMAGE — the transport, carrier, normalizer, and acceptance-6/7 text there are the authority). Research: `.doperpowers/sdd/2026-08-22-f9-wave/r4-image-paste.md`.

## Global Constraints

- Wire shape exactly `{type:"image", source:{type:"base64", media_type, data}}`; assembly text block first, images appended (canon L371395-371427).
- Limits, all enforced at the builder with exact-value boundary tests: 2000×2000 px (1999/2000/2001 cells — the builder decodes PNG IHDR / JPEG SOF itself), 5 MiB base64 input (±1), 512,000-byte per-block post ceiling (±1), 5 MiB per-turn aggregate (± one block). **Once a chip exists, failures degrade to the text block `[Image could not be processed: <reason>]` and the turn still submits.** Only paste-time "no image" inserts nothing (toast).
- Persistence: payloads never in `history.jsonl` or the paste cache (`pasteCache.ts`); volatile stash/undo/queue RETAIN entries; a history line restored after reload submits its literal label; the SDK's own transcript persistence untouched.
- Version skew is LOUD: pre-image host → `stageImage` unknown-op error → client notice; never a stripped text-only turn.
- Staged files: host-owned dir `0700`, files `0600`; client owns until prompt acceptance; host deletes claimed files in `finally`; bounded-age orphan sweep at host start + periodic.
- `turnSeq` reserved synchronously before any file I/O in the prompt handler.
- New public types exported from `src/index.ts`; `npm run build` passes.
- SECURITY: never print/echo/log tokens; live cells via `set -a; . ../.env; set +a`.
- Commands from `CC-to-SDK/harness/`. Never bare `npm test`. Stage explicit paths only. Commit per task, no `Co-Authored-By`, never push.
