# T-ADVCMD Implementation Plan (bl8) — the /advisor command

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-execution to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clone canon 2.1.251's `/advisor` command: the "Advisor (experimental)" dialog (catalog rows +
"No advisor"), client-side eligibility/pairing off canon's static ranks, live mid-session apply via
`applyFlagSettings({advisorModel})`, persisted default, and the startup notification.

**Architecture:** A pure half (`src/tui/advisorModel.ts`: transcribed rank table, catalog, pairing
predicates, every literal, and a pure `applyAdvisorChoice` that returns the action + result string) under
a thin Ink dialog (`AdvisorDialog.tsx`, the ModelPicker/ThemeDialog modal family). The apply channel is a
new `setAdvisorModel(model | null)` on the settings-ops surface beside `setEffort` (host-side
`applyFlagSettings` — canon's own remote path sends the identical request; P119 case 4 verified it
live). `useChat`'s bl7 session-constant `advisorModel` becomes state so the `Advising using {model}` row
tracks changes. Client-side validation is load-bearing: P119 proved the server silently ignores bad
values.

**Tech Stack:** TypeScript, Ink, vitest (`npm run typecheck` / `npm run test:unit` / `npm run test:tui`
from `CC-to-SDK/harness/` — NEVER bare `npm test`).

**Governing docs:** spec `docs/superpowers/specs/2026-08-30-bl8-qy-advisor-design.md` §3 (D7-D12);
canon transcription `.doperpowers/sdd/2026-08-30-bl8-round/research-config-picker.md` §2-3 (dialog `Z`,
`applyAdvisor`, catalog/predicates, "Reusable literals" list) — copy literals from THERE, character for
character.

## Global Constraints

- Canon literals verbatim (research-config-picker.md "Reusable literals"): title
  `Advisor (experimental)`; command description `Let Claude consult a stronger model at key moments`;
  blurb, recommendation (`Recommended setup: ` in suggestion color + the Sonnet/Opus sentence), link
  `https://claude.com/blog/the-advisor-strategy`; results `Advisor disabled` / `Advisor set to {name}`;
  the two `Note:` suffixes (unsupported main model / failed pairing); invalid
  `{name} cannot be used as an advisor. Valid options: fable, opus, sonnet, off`; warning
  `The current main model ({name}) does not support the advisor.`; off row `{label:"No advisor",
  value:"off"}` always last.
- Ranks transcribed from the binary catalog (@155174245-155184801): haiku-4-5 → 1, sonnet-4-5 → 2,
  sonnet-5 → 3, opus-4-7/opus-4-8/opus-5 → 4, fable-5 → 5. Floor `ADVISOR_RANK_FLOOR = 2`
  (canon `Aqt`); eligible advisor = rank ≥ floor; pairing = advisee rank ≤ advisor rank; a main model
  with NO rank entry does not support the advisor.
- Catalog aliases `["fable", "opus", "sonnet"]` in canon's order; values are ALIASES, labels are display
  names. No " (this session only)" suffix (D10: ccx live-applies AND persists). No fable consent flow
  (D12). `/advisor <arg>` accepts catalog aliases, exact catalog-resolved ids, `off`, `unset`; anything
  else gets the canon invalid message (D11).
- Apply order: validate → `setAdvisorModel(resolvedId | null)` → persist pref → update useChat state →
  post result line. A `setAdvisorModel` rejection surfaces as the result line (`advisor: <error>`
  style of the existing mcp toggle arm) and skips the persist.
- Follow `setEffort`'s plumbing EXACTLY for the new settings-op (find every layer:
  `grep -rn "setEffort" src/`). Dense hand-style; ESM `.js`; DI-by-deps; tui tests await a tick before
  writing keys.

- Produces: `commands.ts` entry `{ name: "advisor", summary: "[opus|sonnet|fable|off] — let Claude
  consult a stronger model at key moments" }` (order the aliases as `advisorCatalog()` returns them,
  lower-cased summary per the file's house style — read neighboring entries first).
- Produces: `AdvisorDialog` props `{ current?: string; mainModel?: string; onChoose(choice: string):
  void; onCancel(): void }` — renders title, blurb, conditional unsupported warning, rows
  (`advisorCatalog()` display names + pinned custom current + `No advisor` last, default focus =
  current-or-off), recommendation, link. Esc cancels. Keyboard: the Select primitive the other dialogs
  use.
- Produces: `useChat` — **state + ref pair (plan-review F4: `useState` alone leaves the mount-time
  host-event subscription and every long-lived closure reading the initial value — this file uses refs
  for mutable values for exactly that reason).** `advisorModelRef = useRef(opts.initialAdvisorModel)`
  is the source of truth read by `projectionContext()` (its existing
  `...(advisorModel !== undefined ? { advisorModel } : {})` spread now reads `advisorModelRef.current`);
  a paired state exists only if something in the React tree renders from it directly. The apply path
  writes the ref FIRST, then calls `reconcile()` so the change repaints without waiting for a document
  revision. **Projection cache (F4 second half):** `toolRenderer.tsx` ~:173 documents `advisorModel` as
  deliberately NOT in `knobKey` because it was session-constant — that reasoning is now false. Move
  `advisorModel` INTO `knobKey` and update that comment, or the cached projection serves the old model
  name after `/advisor`.
- Produces: `/advisor` with no arg opens the dialog; with an arg runs `applyAdvisorChoice` directly. On
  action "set": `await session.setAdvisorModel(resolvedId)` (feature-detect the method on the session
  object — older hosts lack it; absent → result line `advisor: not supported by this host`), then
  persist `{ advisorModel: resolvedId }` via prefs, update ref (+ reconcile), append the result message.
  On "off": `setAdvisorModel(null)`, delete the pref key, ref undefined (+ reconcile), append. On
  "invalid": append only, nothing else changes.
