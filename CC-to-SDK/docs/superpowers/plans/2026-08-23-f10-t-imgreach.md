# F10 T-IMGREACH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an image reaches every submit surface ccx owns — the library (`harness.run`/`stream`, `runStructured`, `Session.stream`), the app-server (staged chunks + `turn/startContent`/`turn/steerContent`), and the daemon (`submit_content`) — and no turn strands its own session; Linux and Windows stop refusing BMP and oversized clipboard images; and a user with an image on the clipboard is told so.

**Architecture:** normalizer-first, then outward. `normalizeTurnInput` (`src/session/turnInput.ts`) is already the one seam every surface passes through, so it hardens FIRST — the stranding guarantee, the shared image/block/text caps with one output-accounting algorithm, and base64 canonicalization all land there before a single surface widens, which is what lets each later surface be a transport change rather than a policy change. Only then do the surfaces open, each on its own negotiated step (a new JSON-RPC method pair on the app-server, a new op literal on the daemon) rather than an additive field that an old peer would silently strip. Two leaf modules ride alongside and depend on nothing: `src/media/imageCodec.ts` (pure `node:zlib` PNG/BMP ladder) and the ambient clipboard hint's check-only process seam.

**Tech Stack:** TypeScript ESM (`.js` specifiers), vitest, zod v4, Ink 5 + ink-testing-library, `node:zlib` / `node:string_decoder` (no new runtime dependencies), tmux for pty cells.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-23-f10-wave-design.md` **v4** — Track T-IMGREACH (§I1–I6) plus Global constraints. - [ ] **Step 5: Implement — `src/media/imageDims.ts` first (only if absent), then the normalizer.** The output-accounting algorithm, verbatim:

  ```ts
  const sentinelText = (dropped: number) =>
    `[+${dropped} more blocks dropped: prompt exceeded the ${MAX_CONTENT_BLOCKS}-block limit]`;

  /** ONE algorithm closes BOTH caps (round-3 F4 — the sentinel and the ceiling otherwise conflict at the
   *  joint boundary, where 63 survivors already sit at exactly the ceiling and the sentinel has nowhere to
   *  go). Three phases, in this order, and the order IS the correctness:
   *    (1) block count. The sentinel RESERVES ITS SLOT: when the input overflows, at most
   *        MAX_CONTENT_BLOCKS-1 = 63 input blocks survive and the sentinel is the 64th, so the output
   *        length is never > MAX_CONTENT_BLOCKS for any input.
   *    (2) the text ceiling is measured over the OUTPUT — user text plus the sentinel's own text.
   *    (3) if that total exceeds the ceiling, the USER's retained text is truncated from the LAST text
   *        block backward to `ceiling − sentinel reserve (when a sentinel exists) − suffix reserve`, and
   *        the suffix is appended to the last text block. The sentinel is never truncated.
   *  The RESERVES are upper bounds spent unconditionally, not measured lengths: that is what keeps this a
   *  single pass whose output is a deterministic function of the input rather than of how the sentinel
   *  happened to render. */
  function applyOutputCaps(blocks: UserContentBlock[]): UserContentBlock[] {
    // ── (1) block count
    const overflow = blocks.length > MAX_CONTENT_BLOCKS;
    const kept = overflow ? blocks.slice(0, MAX_CONTENT_BLOCKS - 1) : blocks;
    const sentinel = overflow
      ? sentinelText(blocks.length - (MAX_CONTENT_BLOCKS - 1)).slice(0, SENTINEL_TEXT_RESERVE)
      : undefined;
    const out: UserContentBlock[] = sentinel === undefined ? [...kept] : [...kept, { type: "text", text: sentinel }];

    // ── (2) the ceiling, over the OUTPUT. UTF-16 code units, deliberately: `String#length` is the unit the
    //    cap is stated in, and it is also what bounds the memory a JS string actually holds.
    const userTextIdx: number[] = [];
    let userText = 0;
    for (let i = 0; i < kept.length; i++) {
      const b = out[i]!;
      if (b.type !== "text") continue;
      userTextIdx.push(i); userText += b.text.length;
    }
    if (userText + (sentinel?.length ?? 0) <= MAX_TOTAL_TEXT) return out;
    if (userTextIdx.length === 0) return out;   // nothing of ours to give — the sentinel alone cannot exceed

    // ── (3) truncate from the LAST text block backward
    const target = MAX_TOTAL_TEXT - (sentinel === undefined ? 0 : SENTINEL_TEXT_RESERVE) - TRUNCATION_SUFFIX_RESERVE;
    let excess = userText - target;
    for (let k = userTextIdx.length - 1; k >= 0 && excess > 0; k--) {
      const i = userTextIdx[k]!;
      const text = (out[i] as { type: "text"; text: string }).text;

    const last = userTextIdx[userTextIdx.length - 1]!;
    out[last] = { type: "text", text: (out[last] as { type: "text"; text: string }).text + TRUNCATION_SUFFIX };
    return out;
  }
  ```

```ts
// ── source-size refusal, before any parse
if (buf.length > MAX_SOURCE_BYTES) return { ok: false, reason: `image source exceeds the ${MAX_SOURCE_BYTES}-byte limit` };

// ── declared-pixel refusal, OVERFLOW-SAFE. PNG IHDR carries two uint32s, whose product exceeds 2^53 and
//    therefore loses precision as a JS number — so the comparison is done by DIVISION, never multiplication.
function pixelsWithinBudget(width: number, height: number): boolean {
  if (!Number.isInteger(width) || !Number.isInteger(height) || width <= 0 || height <= 0) return false;
  return width <= Math.floor(MAX_PIXELS / height);
}

// ── inflate capped at the EXACT expected scanline total. One byte over is a zip bomb, not a big image:
//    a well-formed PNG's IDAT stream inflates to exactly (1 filter byte + width*bytesPerPixel) * height.
const expected = (1 + width * bytesPerPixel) * height;
let raw: Buffer;
try { raw = inflateSync(idat, { maxOutputLength: expected }); }
catch { return { ok: false, reason: "PNG image data expands past its declared size (rejected)" }; }
if (raw.length !== expected) return { ok: false, reason: "PNG image data does not match its declared size" };

// ── PNG chunk walk: every length is validated against the buffer BEFORE the slice it authorizes
while (off + 8 <= buf.length) {
  const len = buf.readUInt32BE(off);
  if (len > MAX_SOURCE_BYTES || off + 12 + len > buf.length) return { ok: false, reason: "truncated or malformed PNG chunk" };
  const type = buf.toString("ascii", off + 4, off + 8);
  /* … */ off += 12 + len;                                   // 4 len + 4 type + len data + 4 CRC
}

// ── BMP: every offset/stride/mask range validated against the ACTUAL buffer length before any read
//    (r3 verified real clipboard BMPs are 32bpp BI_BITFIELDS with a 124-byte BITMAPV5HEADER, masks at
//    offsets 54/58/62/66, and a NEGATIVE height meaning top-down rows — a BI_RGB-only bottom-up decoder
//    fails on exactly the BMPs this arm exists to rescue).
const dataOffset = buf.readUInt32LE(10);
const stride = ((width * bitsPerPixel + 31) >> 5) << 2;      // rows are 4-byte aligned
if (dataOffset >= buf.length || stride <= 0 || dataOffset + stride * absHeight > buf.length)
  return { ok: false, reason: "BMP pixel data runs past the end of the buffer" };

// ── the fallback arm for what this decoder does NOT handle: palette (colour type 3), 16-bit depth,
//    Adam7 interlace. Required, not optional (r3): pass through when already within budget, else fail
//    with a real reason rather than silently producing wrong pixels.
if (colourType === 3 || bitDepth === 16 || interlace !== 0) {
  return withinBudget(buf, width, height)
    ? { ok: true, value: { passthrough: buf, width, height } }
    : { ok: false, reason: `unsupported PNG variant (colour type ${colourType}, depth ${bitDepth}, interlace ${interlace}) and over budget` };
}

// ── the single wall-clock guard, checked between stages AND every 64 scanlines inside the two loops
if (deadline.expired()) return { ok: false, reason: `image processing exceeded the ${PROCESSING_BUDGET_MS}ms budget` };
```

  ```ts
    const decoder = new StringDecoder("utf8");         // a split multi-byte character must not corrupt
    let buf = "";
    let deadline: NodeJS.Timeout | undefined;
    const armDeadline = () => {
      if (deadline) return;

        // A byte cap alone is not a bound: one byte held forever still exhausts connections (round-2 F11).
        console.error(`daemon: dropping connection — partial line held ${DAEMON_PARTIAL_LINE_MS}ms with no newline`);
        sock.destroy();
      }, DAEMON_PARTIAL_LINE_MS);
      (deadline as { unref?: () => void }).unref?.();
    };
    const onData = (d: Buffer) => {
      buf += decoder.write(d);
      const nl = buf.indexOf("\n");
      if (nl < 0) {
        if (Buffer.byteLength(buf, "utf8") > DAEMON_MAX_FRAME_BYTES) { sock.destroy(); return; }
        armDeadline(); return;
      }
      if (deadline) { clearTimeout(deadline); deadline = undefined; }
      sock.off("data", onData);                        // one op per connection (first line)
      const line = buf.slice(0, nl);
      if (Buffer.byteLength(line, "utf8") > DAEMON_MAX_FRAME_BYTES) { sock.destroy(); return; }
      void this.handle(sock, line);
    };
    sock.on("data", onData);
    // EOF with a non-empty partial buffer is a DROP, not a parse: a half-written frame is not an op.
    sock.on("end", () => { if (deadline) clearTimeout(deadline); if (buf.length) sock.destroy(); });
    sock.on("close", () => { if (deadline) clearTimeout(deadline); });
    sock.on("error", () => {});
  ```

## Spec-drift notes

Read before implementing; each is a place the tree contradicts, or is silently affected by, the spec as written.

1. **`test/integration/host-image-transport.test.ts:374-388` asserts the shape I1 changes.** Its "final-review finding 2" cell pins an image-only loopback submit as `assembled[0] === {type:"text", text:""}`. That empty block is exactly what probe 100's C cell proved does not rescue a session. Task 1 Step 6 updates the assertion to the labelled form — the change *is* the fix landing on the REPL wire, and the cell's comment must say so rather than the path being exempted.

2. **The queue's byte accounting changes for strings, not only for arrays.** `src/appserver/queue.ts:45` measures `Buffer.byteLength(q.input, "utf8")`; the spec's contract is `Buffer.byteLength(JSON.stringify(input))` of the normalized turn input. Applying it uniformly (the only way one function serves both forms) adds JSON quoting and escaping to a string entry's charge. Existing queue boundary tests shift by that amount and must be updated with a comment naming the cause.

3. **The total queued-bytes cap moves 1 MiB → 4 MiB.** `MAX_QUEUED_BYTES` is currently the *total* cap; under the spec 1 MiB becomes the *per-entry* cap and 4 MiB the total. `turns.ts`'s `QUEUE_FULL` message table is spelled off the constants and gains a third arm (`"entry"`); the two existing messages' wording must stay derived from the constants, never re-typed.

4. **`MAX_IMAGES_PER_PROMPT` currently lives in `src/host/imageStaging.ts:33` and `src/client/chatAdapter.ts:13` imports it from there.** Task 2 moves the definition to `src/media/imageDims.ts` and leaves a re-export at the old site so that import keeps resolving; T-MAINT item 3 completes the same move for `pngDimensions`/`jpegDimensions`/`MAX_DIMENSION`/`POST_PROCESS_BYTE_BUDGET`. Coordinate through the file, not through a second module.

5. **`parse.ts:132` collapses focus-in and focus-out into one `ignored("focus", raw)`.** The edge semantics I6 needs live in `raw`'s final byte (`I` vs `O`). Task 7 reads it at the route rather than changing the parser's event shape — a new event kind would ripple through every `InputEvent` consumer for no behavioural gain.

6. **`Footer.tsx:152-153` states "SEVEN surfaces post at `priority:\"immediate\"`" and enumerates them.** That census is load-bearing for the fullscreen right-region rule. Task 7 makes it eight; the comment must be updated in the same commit as the poster, and the grep-count assertion added so the next poster cannot land silently.

7. **`src/appserver/schema/index.ts` is walked by the artifact generator and a drift gate.** A shipped method missing from `methodSchemas` is a build failure, so the three new entries and the regenerated `schema/json/{stable,experimental}/appserver.json` belong in Task 5's single commit. All three are `experimental: true`: `image/stage` and the two content methods ride seams (staged upload, `Query.streamInput`) with no stability promise, exactly as `turn/steer` does today.

8. **Out of scope, deliberately (spec Non-goals) — do not build:** the app-server `initialize` capability list; the fleet staging-client (F10 errors loudly instead); the opportunistic `magick`/`ffmpeg` rung; darwin `sips` unification; `ccx -p` image flags; swarm/kairos seed widening; any stranded-session recovery scan (owner fork: **fix forward only**).
