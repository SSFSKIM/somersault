# F10 T-IMGREACH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-execution to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an image reaches every submit surface ccx owns — the library (`harness.run`/`stream`, `runStructured`, `Session.stream`), the app-server (staged chunks + `turn/startContent`/`turn/steerContent`), and the daemon (`submit_content`) — and no turn strands its own session; Linux and Windows stop refusing BMP and oversized clipboard images; and a user with an image on the clipboard is told so.

**Architecture:** normalizer-first, then outward. `normalizeTurnInput` (`src/session/turnInput.ts`) is already the one seam every surface passes through, so it hardens FIRST — the stranding guarantee, the shared image/block/text caps with one output-accounting algorithm, and base64 canonicalization all land there before a single surface widens, which is what lets each later surface be a transport change rather than a policy change. Only then do the surfaces open, each on its own negotiated step (a new JSON-RPC method pair on the app-server, a new op literal on the daemon) rather than an additive field that an old peer would silently strip. Two leaf modules ride alongside and depend on nothing: `src/media/imageCodec.ts` (pure `node:zlib` PNG/BMP ladder) and the ambient clipboard hint's check-only process seam.

**Task shape (r2 — plan review F18/F19/F20):** fourteen tasks, each independently green and independently reviewable. The codec is three tasks (bounded decode → encode/downscale → clipboard dispatch) and the app-server is five (stage registry → queue migration → engine/fleet capabilities → RPC schema + `startContent` → steer + display integration), because parser safety, wire risk and resource-lifecycle risk are three different review problems and one commit that mixes them cannot be reverted in parts.

**Tech Stack:** TypeScript ESM (`.js` specifiers), vitest, zod v4, Ink 5 + ink-testing-library, `node:zlib` / `node:string_decoder` (no new runtime dependencies), tmux for pty cells.

**Spec:** `CC-to-SDK/docs/superpowers/specs/2026-08-23-f10-wave-design.md` **v4.1** — Track T-IMGREACH (§I1–I6), the **Wave assembly** section, plus Global constraints. Every numeric limit, accounting rule and skew semantic there is BINDING and quoted verbatim below. Research: `.doperpowers/sdd/2026-08-23-f10-wave/research/r3-image-reach.md`; probe `CC-to-SDK/probes/probes/100-listsessions-image-only.ts`.

```ts
/** From the media substrate the base branch already carries. `MAX_IMAGES_PER_PROMPT` is ccx's defensive
 *  ceiling on how many images ONE prompt may hold; enforcing it HERE (spec I2 / review F3) is what makes
 *  it bind every surface rather than only host staging, which every non-host caller bypassed. Excess
 *  images degrade to the failure text block; the turn still submits. */
import { MAX_IMAGES_PER_PROMPT } from "../media/imageDims.js";
/** base64 STRING-length input ceiling, checked BEFORE `Buffer.from` allocates. Exported so the
 *  app-server's staged-upload cap (I3) derives from THIS number instead of a second 5 MiB literal. */
export const MAX_BASE64_INPUT_BYTES: number;           // 5 * 1024 * 1024 — was module-private
/** Counts the normalized OUTPUT, sentinel INCLUDED (round-2 F5): when a sentinel is emitted at most 63
 *  input blocks survive, so the output length never exceeds 64 for any input. */
export const MAX_CONTENT_BLOCKS = 64;
/** UTF-16 code units, summed over every text block of the OUTPUT (synthetic failure text, the I1 stranding
 *  label and the sentinel all included). Applies to the BARE-STRING form too — a string is one text block. */
export const MAX_TOTAL_TEXT = 1_048_576;
/** Units reserved out of MAX_TOTAL_TEXT for the block-collapse sentinel; the sentinel is hard-capped at
 *  this and is NEVER truncated. */
export const SENTINEL_TEXT_RESERVE = 256;
/** Units reserved out of MAX_TOTAL_TEXT for the truncation suffix. */
export const TRUNCATION_SUFFIX_RESERVE = 64;
export const TRUNCATION_SUFFIX = "\n[… prompt text truncated to fit the size limit]";

/** ONE image block's verdict, exported so a caller that validates images ONE AT A TIME as they arrive —
 *  the app-server's stage registry (Task 7), which must validate exactly once, at stage completion — uses
 *  THIS function rather than a second copy of the four caps. Returns the CANONICALIZED block on success,
 *  plus its decoded byte count so the caller can do per-turn aggregate accounting later WITHOUT decoding
 *  again. The per-turn aggregate cap is deliberately NOT applied here: it is a property of a turn, and a
 *  stage does not know which turn it will join. */
export function validateImageBlock(block: UserContentBlock & { type: "image" }):
  | { ok: true; block: UserContentBlock & { type: "image" }; decodedBytes: number }
  | { ok: false; reason: string };

/** The second half of `normalizeTurnInput`: the I1 stranding pass plus `applyOutputCaps`, over blocks whose
 *  images have ALREADY been validated and canonicalized by `validateImageBlock`. Exported for exactly one
 *  reason (plan-review r2 F-STAGE): re-running the full normalizer over staged blocks would decode every
 *  image a SECOND time, which is the cost the validate-once contract exists to avoid. Text handling is
 *  identical either way, so the two paths cannot drift on anything but the decode. */
export function normalizeValidatedBlocks(blocks: UserContentBlock[]): UserContentBlock[];

/** Per-turn aggregate ceiling on the SUM of passing images' decoded bytes — exported so the aggregate can
 *  be closed from CACHED byte counts (again: no second decode). */
export const MAX_AGGREGATE_BYTES: number;   // 5 * 1024 * 1024 — was module-private
```

`normalizeTurnInput(array)` is now, definitionally, `normalizeValidatedBlocks(validateEachImage(array))` — one composition, so every property proven of the normalizer holds of the staged path too, minus the decode.

Contract additions to `normalizeTurnInput`:

1. **Canonical base64** — every image block that PASSES its caps is rebuilt with `decoded.toString("base64")` (round-3 F3). Padding and whitespace never survive; the daemon's 24 MiB frame derivation (Task 12) rests on this guarantee.

  ```ts
  const sentinelText = (dropped: number) =>
    `[+${dropped} more blocks dropped: prompt exceeded the ${MAX_CONTENT_BLOCKS}-block limit]`;

  /** ONE algorithm closes BOTH caps (round-3 F4 — the sentinel and the ceiling otherwise conflict at the
   *  joint boundary, where 63 survivors already sit at exactly the ceiling and the sentinel has nowhere to
   *  go). Three phases, in this order, and the order IS the correctness:
   *    (1) block count. The sentinel RESERVES ITS SLOT: when the input overflows, at most
   *        MAX_CONTENT_BLOCKS-1 = 63 input blocks survive and the sentinel is the 64th, so the output
   *        length is never > MAX_CONTENT_BLOCKS for any input.
   *    (2) the text ceiling is measured over the OUTPUT — user text plus the sentinel's own text.
   *    (3) if that total exceeds the ceiling, the USER's retained text is truncated from the LAST text
   *        block backward to `ceiling − sentinel reserve (when a sentinel exists) − suffix reserve`, and
   *        the suffix is appended to the last text block. The sentinel is never truncated.
   *  The RESERVES are upper bounds spent unconditionally, not measured lengths: that is what keeps this a
   *  single pass whose output is a deterministic function of the input rather than of how the sentinel
   *  happened to render. */
  function applyOutputCaps(blocks: UserContentBlock[]): UserContentBlock[] {
    // ── (1) block count
    const overflow = blocks.length > MAX_CONTENT_BLOCKS;
    const kept = overflow ? blocks.slice(0, MAX_CONTENT_BLOCKS - 1) : blocks;
    const sentinel = overflow
      ? sentinelText(blocks.length - (MAX_CONTENT_BLOCKS - 1)).slice(0, SENTINEL_TEXT_RESERVE)
      : undefined;
    const out: UserContentBlock[] = sentinel === undefined ? [...kept] : [...kept, { type: "text", text: sentinel }];

    // ── (2) the ceiling, over the OUTPUT. UTF-16 code units, deliberately: `String#length` is the unit the
    //    cap is stated in, and it is also what bounds the memory a JS string actually holds.
    const userTextIdx: number[] = [];
    let userText = 0;
    for (let i = 0; i < kept.length; i++) {
      const b = out[i]!;
      if (b.type !== "text") continue;
      userTextIdx.push(i); userText += b.text.length;
    }
    if (userText + (sentinel?.length ?? 0) <= MAX_TOTAL_TEXT) return out;
    if (userTextIdx.length === 0) return out;   // nothing of ours to give — the sentinel alone cannot exceed

    // ── (3) truncate from the LAST text block backward
    const target = MAX_TOTAL_TEXT - (sentinel === undefined ? 0 : SENTINEL_TEXT_RESERVE) - TRUNCATION_SUFFIX_RESERVE;
    let excess = userText - target;
    for (let k = userTextIdx.length - 1; k >= 0 && excess > 0; k--) {
      const i = userTextIdx[k]!;
      const text = (out[i] as { type: "text"; text: string }).text;
      const drop = Math.min(excess, text.length);
      out[i] = { type: "text", text: text.slice(0, text.length - drop) };
      excess -= drop;
    }
    const last = userTextIdx[userTextIdx.length - 1]!;
    out[last] = { type: "text", text: (out[last] as { type: "text"; text: string }).text + TRUNCATION_SUFFIX };
    return out;
  }
  ```

  ```ts
  export function normalizeTurnInput(input: UserTurnInput): UserTurnInput {
    if (typeof input === "string") return (applyOutputCaps([{ type: "text", text: input }])[0] as { text: string }).text;
    let aggregate = 0, imageOrdinal = 0;

      if (++imageOrdinal > MAX_IMAGES_PER_PROMPT)

        return { type: "text", text: `[Image could not be processed: turn's total image size exceeds the ${MAX_AGGREGATE_BYTES}-byte limit]` };
      aggregate += v.decodedBytes;
      return v.block;
    });
    return normalizeValidatedBlocks(validated);
  }
  ```

**THE PROCESSING-BOUND CONTRACT — spec v4.1 §I5, amended at plan review. Read before writing a line:**

> The binding CPU/allocation bound is **structural**: every inflate call passes `maxOutputLength` = the exact expected scanline total, so a hostile stream's work is bounded by the output cap and one byte over throws (this is also the zip-bomb arm); the **2 s wall guard is a cooperative belt** checked between pipeline stages and every 64 scanlines, documented as such. The hostile-fixture tests assert the structural cap fires (output-capped bomb → typed failure), not wall-clock interruption.

Concretely, for this plan: `PROCESSING_BUDGET_MS` exists, is checked cooperatively, and is **documented in the source as a belt**. No test in this track asserts that a hostile input is *interrupted* by the clock, and no comment claims a hang is impossible because of it. What is asserted is stronger and actually true: with the deadline stubbed to **never expire**, every hostile fixture still returns a coded failure — so the structural bound, not the clock, is what carries the guarantee.

**Interfaces:**

```ts
// src/media/imageCodec.ts — a LEAF: node:zlib only, no fs, no child_process, no tui import.

/** Decode results are a UNION, never one shape with optional fields (plan-review r2 F-CODEC). The
 *  palette / 16-bit / interlaced arm CANNOT produce pixels, so a caller that forgets it must fail to
 *  compile rather than read `undefined` off a `pixels` field that a passthrough never had. */
export interface DecodedPixels { kind: "pixels"; width: number; height: number; pixels: Buffer }   // RGBA, 4 B/px
export interface PassthroughImage { kind: "passthrough"; width: number; height: number; data: Buffer; mediaType: string }
export type DecodedImage = DecodedPixels | PassthroughImage;

/** Failures are CODED. Hostile-input cells assert the CODE, so rewording a reason string cannot quietly
 *  turn a boundary assertion into a tautology; `reason` stays for humans and for the clipboard's
 *  user-facing failure text. */
export type CodecFailureCode =
  | "source-too-large"      // refused on buffer length, before any parse
  | "pixel-budget"          // declared width*height over MAX_PIXELS, checked overflow-safe
  | "inflate-overrun"       // the STRUCTURAL bound fired: inflate produced more than the declared total
  | "malformed"             // truncated/overlong chunk, forged BMP offset or stride, bad signature
  | "unsupported-variant"   // palette / 16-bit / interlaced, and not passthrough-able
  | "budget-exceeded"       // the cooperative wall belt tripped between stages
  | "encode-floor";         // Task 5's arm — declared here so the union is closed from the start
export type CodecResult<T> = { ok: true; value: T } | { ok: false; code: CodecFailureCode; reason: string };

/** NORMATIVE hostile-input bounds (spec I5). Each is a REFUSAL BEFORE ALLOCATION. */
export const MAX_SOURCE_BYTES = 10 * 1024 * 1024;         // source bytes
export const MAX_PIXELS = 25_000_000;                     // declared width*height, overflow-safe
/** The COOPERATIVE belt (spec v4.1). Not an interrupt: a synchronous `inflateSync` cannot be preempted by
 *  a clock, and the bound that actually protects this module is `maxOutputLength` on every inflate. This
 *  guard catches the *other* shape of slowness — a legal, in-budget image on a pathologically slow host —
 *  at stage boundaries and every 64 scanlines. Documented here so no future reader mistakes it for a
 *  hang guarantee. */
export const PROCESSING_BUDGET_MS = 2000;

export interface Deadline { expired(): boolean }
export function deadlineFrom(now?: () => number, budgetMs?: number): Deadline;
/** For tests that must prove the STRUCTURAL bound alone carries a fixture: a belt that never trips. */
export const NEVER_EXPIRES: Deadline;

export function decodePng(buf: Buffer, deadline: Deadline): CodecResult<DecodedImage>;
export function decodeBmp(buf: Buffer, deadline: Deadline): CodecResult<DecodedImage>;
/** Sniffs PNG (`\x89PNG`) / BMP (`BM`) and routes; anything else fails `malformed`. */
export function decodeImage(buf: Buffer, mediaType: string, deadline: Deadline): CodecResult<DecodedImage>;
```

**Bounds, as code — these MUST appear in the implementation:**

```ts
// ── source-size refusal, before any parse
if (buf.length > MAX_SOURCE_BYTES)
  return { ok: false, code: "source-too-large", reason: `image source exceeds the ${MAX_SOURCE_BYTES}-byte limit` };

// ── declared-pixel refusal, OVERFLOW-SAFE. PNG IHDR carries two uint32s, whose product exceeds 2^53 and
//    therefore loses precision as a JS number — so the comparison is done by DIVISION, never multiplication.
function pixelsWithinBudget(width: number, height: number): boolean {
  if (!Number.isInteger(width) || !Number.isInteger(height) || width <= 0 || height <= 0) return false;
  return width <= Math.floor(MAX_PIXELS / height);
}

// ── THE STRUCTURAL BOUND. inflate capped at the EXACT expected scanline total: one byte over is a zip
//    bomb, not a big image. A well-formed PNG's IDAT stream inflates to exactly
//    (1 filter byte + width*bytesPerPixel) * height. `maxOutputLength` makes zlib itself stop there — the
//    work and the allocation are both bounded by a number we computed from the header we already
//    validated, which is why this and not the wall clock is the binding guarantee.
const expected = (1 + width * bytesPerPixel) * height;
let raw: Buffer;
try { raw = inflateSync(idat, { maxOutputLength: expected }); }
catch { return { ok: false, code: "inflate-overrun", reason: "PNG image data expands past its declared size (rejected)" }; }
if (raw.length !== expected)
  return { ok: false, code: "malformed", reason: "PNG image data does not match its declared size" };

// ── PNG chunk walk: every length is validated against the buffer BEFORE the slice it authorizes
while (off + 8 <= buf.length) {
  const len = buf.readUInt32BE(off);
  if (len > MAX_SOURCE_BYTES || off + 12 + len > buf.length)
    return { ok: false, code: "malformed", reason: "truncated or malformed PNG chunk" };
  const type = buf.toString("ascii", off + 4, off + 8);
  /* … */ off += 12 + len;                                   // 4 len + 4 type + len data + 4 CRC
}

// ── BMP: every offset/stride/mask range validated against the ACTUAL buffer length before any read
//    (r3 verified real clipboard BMPs are 32bpp BI_BITFIELDS with a 124-byte BITMAPV5HEADER, masks at
//    offsets 54/58/62/66, and a NEGATIVE height meaning top-down rows — a BI_RGB-only bottom-up decoder
//    fails on exactly the BMPs this arm exists to rescue).
const dataOffset = buf.readUInt32LE(10);
const stride = ((width * bitsPerPixel + 31) >> 5) << 2;      // rows are 4-byte aligned
if (dataOffset >= buf.length || stride <= 0 || dataOffset + stride * absHeight > buf.length)
  return { ok: false, code: "malformed", reason: "BMP pixel data runs past the end of the buffer" };

// ── the PASSTHROUGH arm for what this decoder does NOT handle: palette (colour type 3), 16-bit depth,
//    Adam7 interlace. Required, not optional (r3). It returns the OTHER member of the union — never a
//    DecodedPixels with a missing field.
if (colourType === 3 || bitDepth === 16 || interlace !== 0) {
  return buf.length <= byteBudget
    ? { ok: true, value: { kind: "passthrough", width, height, data: buf, mediaType: "image/png" } }
    : { ok: false, code: "unsupported-variant",
        reason: `unsupported PNG variant (colour type ${colourType}, depth ${bitDepth}, interlace ${interlace}) and over budget` };
}

// ── the COOPERATIVE belt, checked between stages AND every 64 scanlines inside the two loops.
//    NOT an interrupt — see the PROCESSING_BUDGET_MS doc comment.
if (deadline.expired())
  return { ok: false, code: "budget-exceeded", reason: `image processing exceeded the ${PROCESSING_BUDGET_MS}ms budget` };
```

```ts
    // budget, fail with the variant code — there is no ladder rung available.

    return v.data.length <= byteBudget && Math.max(v.width, v.height) <= maxDimension
      ? { ok: true, value: { data: v.data, mediaType: "image/png", dimensions: { width: v.width, height: v.height } } }
      : { ok: false, code: "unsupported-variant",
          reason: `image uses a PNG variant this build cannot resize (${v.width}x${v.height}, ${v.data.length} bytes)` };
  }
  case "pixels":
    return encodeLadder(decoded.value, maxDimension, byteBudget, deadline);
  default: {
    const _exhaustive: never = decoded.value;         // a new union member must break the BUILD, not runtime
    return _exhaustive;
  }
}
```

```ts
// src/appserver/imageStage.ts
/** Per-image encoded cap = the NORMALIZER's 5 MiB input ceiling, imported, never a second literal. */
import { MAX_BASE64_INPUT_BYTES, validateImageBlock, type UserContentBlock } from "../session/turnInput.js";

export const IMAGE_STAGE_CHUNK_MAX = 128 * 1024;            // base64 bytes of ONE chunk's `data`
export const IMAGE_MEDIA_TYPES = ["image/png", "image/jpeg", "image/gif", "image/webp"] as const;
export const MAX_STAGES_PER_CONNECTION = 4;
export const MAX_STAGED_BYTES_GLOBAL = 32 * 1024 * 1024;    // across ALL connections (round-2 F7:
export const MAX_STAGES_GLOBAL = 64;                        // per-connection caps alone are unbounded
                                                            // under unbounded connections)
export const STAGE_IDLE_MS = 60_000;                        // since the LAST chunk
export const STAGE_ABSOLUTE_MS = 600_000;                   // 10 min per stage, from the first chunk

/** What a COMPLETED stage holds. Validation and canonicalization happen ONCE, at completion (round-3 F5),
 *  through the injected validator. `decodedBytes` rides along so the per-turn aggregate can be closed from
 *  the CACHE — the reservation path must never decode again (plan-review r2 F-STAGE). */
export interface CompletedStage { block: UserContentBlock; decodedBytes: number; charge: number }

/** An EXCLUSIVE reservation (plan-review r2 F-STAGE). The earlier `claim`/`commit` pair could not express
 *  rollback: queue admission happens AFTER the claim, so a refused admission either wedged the stage
 *  forever (if claim reserved) or let two concurrent requests consume the same stage (if it did not).
 *  A reservation takes the stages out of circulation, and exactly one of `commit`/`abort` releases it. */
export interface StageReservation {
  readonly token: string;
  /** The cached, already-canonical blocks, in the order the ids were given. */
  readonly blocks: readonly UserContentBlock[];
  readonly decodedBytes: number;   // summed, from the cache
  readonly charge: number;         // summed serialized-queue bytes, from the cache
}

export type StageResult =
  | { ok: true; complete: false }
  | { ok: true; complete: true }
  | { ok: false; code: number; message: string };

/** Everything time- or policy-dependent is injected, so every cell below is deterministic and the
 *  validate-once contract is observable with a spy rather than inferred. */
export interface ImageStageDeps {
  now?: () => number;
  /** Defaults to `validateImageBlock` (Task 2). ONE image, ONE decode. */
  validate?: (block: UserContentBlock & { type: "image" }) => ReturnType<typeof validateImageBlock>;
}

export class ImageStageRegistry {
  constructor(deps?: ImageStageDeps);
  /** Feeds one chunk. Refuses BEFORE any allocation when `bytesTotal` exceeds MAX_BASE64_INPUT_BYTES, when
   *  `data` exceeds IMAGE_STAGE_CHUNK_MAX, on a bad/missing first-chunk mediaType, on an out-of-order or
   *  duplicate `seq`, on assembled bytes exceeding `bytesTotal`, and on any of the four caps. On the LAST
   *  chunk it runs the injected validator exactly once and caches the result; a stage whose bytes are not
   *  a decodable image FAILS HERE, with the reason on the completion reply — never at reservation. */
  chunk(connId: number, p: ImageStageChunk): StageResult;
  /** ATOMIC and EXCLUSIVE: takes every id or NONE, and the taken stages are unreservable until the token
   *  is settled. Returns the CACHED blocks — no decode happens on this path. */
  reserve(connId: number, stageIds: readonly string[]): { ok: true; reservation: StageReservation } | { ok: false; message: string };
  /** Settles a reservation by consuming it: the stages are deleted and their bytes released. Called only
   *  once the turn has actually been admitted. Unknown/settled token → throws (a programming error). */
  commit(token: string): void;
  /** Settles a reservation by RELEASING it: the stages return to circulation and keep their original
   *  deadlines — a refused queue admission or a capability refusal costs the client nothing but a retry. */
  abort(token: string): void;
  /** Idle + absolute expiry sweep. A RESERVED stage is never swept; its deadline resumes on abort. */
  sweep(): void;
  dropConnection(connId: number): void;
  /** READ-ONLY, for tests and for the server's own logging. Never a mutation seam. */
  stats(): { stagedBytes: number; stageCount: number; reservedCount: number; connections: number };
}
```

```ts
/** The prompt-submitting runner, shared by `turn/start`, `turn/startContent` and the queue drain. It now
 *  ROUTES on the input's form, which is the whole point of this task: a string goes to `submit` (the
 *  unchanged, always-present contract) and an array goes to `submitContent` (the optional capability).
 *  There is no flattening arm. An array reaching a string-only engine is a REFUSAL, not a downgrade —
 *  silently dropping a user's image and running the text is the F9 failure this wave exists to end. */
function submitRunner(srv: AppServer, record: ThreadRecord, input: UserTurnInput) {
  return (turnId: string, mapper: TurnMapper) => {
    const userUuid = randomUUID();
    // ONE display string for both forms, so a live user item and its replayed twin are one function's
    // output (Task 11 wires the replay half).
    emitItems(srv, record, turnId, [{ kind: "completed", item: userItem(flattenForDisplay(input), userUuid) }]);
    const onMessage = (m: unknown) => emitItems(srv, record, turnId, mapper.ingest(m));
    if (typeof input === "string") return record.session.submit(input, onMessage, { uuid: userUuid });
    const submitContent = record.session.submitContent;
    if (!submitContent) throw new EngineCapabilityError("engine does not support content submission");
    return submitContent.call(record.session, input, onMessage, { uuid: userUuid });
  };
```

```ts
// src/daemon/types.ts
const userContentBlock = z.discriminatedUnion("type", [
  z.object({ type: z.literal("text"), text: z.string() }),
  z.object({ type: z.literal("image"), source: z.object({ type: z.literal("base64"), media_type: z.string().min(1), data: z.string() }) }),
]);
/** A NEW OP LITERAL, not a widened `prompt` field: a discriminated union cannot ignore a discriminant it
 *  does not have, whereas an additive field on `submit` would be silently stripped by an old daemon's
 *  schema (Zod strips unknown keys) and run a text-only turn with nobody told. */
const submitContentOp = z.object({ op: z.literal("submit_content"), id: z.string(), input: z.array(userContentBlock).min(1) });

/** Inbound frame cap, DERIVED FROM THE CANONICAL CONTENT MAXIMUM (round-2 F9 + round-3 F3):
 *    20 images × ~683 KB canonical base64 ≈ 13.7 MiB      (the base64 alphabet needs no JSON escapes)
 *  + MAX_TOTAL_TEXT (1,048,576 UTF-16 units) × 6 bytes/unit worst-case JSON-escaped ≈ 6 MiB
 *  + envelope overhead                                     → ~20 MiB, +20% margin → 24 MiB.
 *  v3's 16 MiB was wrong twice: it used 2 bytes per UTF-16 unit where the wire is UTF-8 JSON (escapes cost
 *  up to 6), and it admitted non-canonical whitespace-padded base64 that could stretch an admitted frame
 *  toward 100 MiB. Both halves are closed here AND upstream: the client runs `normalizeTurnInput` before
 *  transport (it is in-process with the library) and the normalizer canonicalizes every passing image's
 *  data to `decoded.toString("base64")`, so padding and whitespace never reach this socket. */
export const DAEMON_MAX_FRAME_BYTES = 24 * 1024 * 1024;
/** A partial line older than this without a newline drops the connection with a logged reason (round-2
 *  F11: one byte held forever still exhausts connections, so a byte cap alone is not a bound). */
export const DAEMON_PARTIAL_LINE_MS = 10_000;

// src/daemon/connect.ts
/** The client-side mapping the old peer cannot express (review F8). A pre-F10 daemon answers
 *  `bad request: …` for the new literal — indistinguishable, from the server's side, from a genuine
 *  payload error. But the CLIENT knows the payload is schema-valid (it built it and preflighted it), so a
 *  `bad request`-class answer to `submit_content` means exactly one thing. */
export const DAEMON_IMAGE_SKEW_NOTICE = "daemon does not support image submission (pre-F10 daemon)";
/** Refused CLIENT-SIDE, before a byte is written, when the serialized op exceeds DAEMON_MAX_FRAME_BYTES. */
export class DaemonFrameTooLargeError extends Error { readonly bytes: number; readonly limit: number }
export interface DaemonClient {
  /** BLOCK ARRAYS ONLY — deliberately NOT `UserTurnInput` (plan-review r2 F-DAEMON, verified: the
   *  `submit_content` schema's `input` is `z.array(userContentBlock).min(1)`, and `normalizeTurnInput`
   *  preserves a bare string as a string, so a `UserTurnInput`-typed method would let a perfectly typed
   *  call be refused on the wire as `invalid op payload`). A string has an op of its own and always did:
   *  `submit`. The type is the routing rule, so the wrong call cannot compile.
   *
   *  Normalizes (so the wire carries the normalizer's canonical output), preflights the serialized size,
   *  then sends. Maps any `bad request`-class refusal to DAEMON_IMAGE_SKEW_NOTICE. */
  submitContent(id: string, blocks: UserContentBlock[], onChunk: (m: unknown) => void): Promise<{ result: unknown }>;
}

/** The one place a caller holding a `UserTurnInput` union turns it into a call — strings to `submit`,
 *  arrays to `submitContent`. Exported beside the client rather than left to each caller, for the same
 *  reason the app-server's drain has one dispatcher (Task 8): two call sites choosing independently is
 *  how one of them ends up flattening an image into text. */
export function daemonSubmitTurn(
  client: DaemonClient, id: string, input: UserTurnInput, onChunk: (m: unknown) => void,
): Promise<{ result: unknown }> {
  return typeof input === "string" ? client.submit(id, input, onChunk) : client.submitContent(id, input, onChunk);
}

// src/daemon/supervisor.ts
async submit(id: string, prompt: UserTurnInput, onMessage: (m: unknown) => void): Promise<TurnOutcome>;
```

  ```ts
    const decoder = new StringDecoder("utf8");         // a split multi-byte character must not corrupt
    let buf = "";
    let deadline: NodeJS.Timeout | undefined;
    const armDeadline = () => {
      if (deadline) return;
      deadline = setTimeout(() => {
        // A byte cap alone is not a bound: one byte held forever still exhausts connections (round-2 F11).
        console.error(`daemon: dropping connection — partial line held ${DAEMON_PARTIAL_LINE_MS}ms with no newline`);
        sock.destroy();

      (deadline as { unref?: () => void }).unref?.();
    };
    const onData = (d: Buffer) => {
      buf += decoder.write(d);
      const nl = buf.indexOf("\n");
      if (nl < 0) {
        if (Buffer.byteLength(buf, "utf8") > DAEMON_MAX_FRAME_BYTES) { sock.destroy(); return; }
        armDeadline(); return;
      }
      if (deadline) { clearTimeout(deadline); deadline = undefined; }
      sock.off("data", onData);                        // one op per connection (first line)
      const line = buf.slice(0, nl);
      if (Buffer.byteLength(line, "utf8") > DAEMON_MAX_FRAME_BYTES) { sock.destroy(); return; }
      void this.handle(sock, line);
    };
    sock.on("data", onData);
    // EOF with a non-empty partial buffer is a DROP, not a parse: a half-written frame is not an op.
    sock.on("end", () => { if (deadline) clearTimeout(deadline); if (buf.length) sock.destroy(); });
    sock.on("close", () => { if (deadline) clearTimeout(deadline); });
    sock.on("error", () => {});
  }
  ```

## Spec-drift notes

Read before implementing; each is a place the tree contradicts, or is silently affected by, the spec as written.

1. **`test/integration/host-image-transport.test.ts:374-388` looks like it asserts the shape I1 changes, and does not.** Its "final-review finding 2" cell pins an image-only loopback submit as `assembled[0] === {type:"text", text:""}`. Verified at plan review: `session` there is a fake **HostSession** (`:49-66`), and `normalizeTurnInput` runs one layer below it inside `Session`'s `userTurn` builder (`src/session/session.ts:36-38`) — so this capture records the **host-assembled** array and the empty block is correct on that seam. The assertion **stays unchanged**; the label is observed at the builder in Task 1 Step 3b. The only permitted edit is the boundary comment in Task 1 Step 6. An implementation that "fixes" this test by moving normalization into the host has broken the governing contract.

2. **The queue's byte accounting changes for strings, not only for arrays.** `src/appserver/queue.ts:45` measures `Buffer.byteLength(q.input, "utf8")`; the spec's contract is `Buffer.byteLength(JSON.stringify(input))` of the normalized turn input. Applying it uniformly (the only way one function serves both forms) adds JSON quoting and escaping to a string entry's charge. Existing queue boundary tests shift by that amount and must be updated with a comment naming the cause.

3. **The total queued-bytes cap moves 1 MiB → 4 MiB.** `MAX_QUEUED_BYTES` is currently the *total* cap; under the spec 1 MiB becomes the *per-entry* cap and 4 MiB the total. `turns.ts`'s `QUEUE_FULL` message table is spelled off the constants and gains a third arm (`"entry"`); the two existing messages' wording must stay derived from the constants, never re-typed.

4. **The media substrate arrives with the base branch — this track must not touch it.** On bare `main`, `MAX_IMAGES_PER_PROMPT` lives at `src/host/imageStaging.ts:33` and is imported by `src/host/host.ts:4` and `src/client/chatAdapter.ts:13`. **That is not the tree this track starts from.** Per spec v4.1's Wave assembly, `f10-imgreach` branches from `f10-maint` after its Task 1 commit, by which point `src/media/imageDims.ts` exists with all five exports, the old definition is deleted, and both real consumers are repointed. So there is nothing to move and nothing to shim: Task 2 imports the constant and stops. Creating the file, or leaving a re-export at the old site, would collide with the deletion T-MAINT already landed.

5. **`parse.ts:132` collapses focus-in and focus-out into one `ignored("focus", raw)`.** The edge semantics I6 needs live in `raw`'s final byte (`I` vs `O`). Task 13 reads it at the route rather than changing the parser's event shape — a new event kind would ripple through every `InputEvent` consumer for no behavioural gain.

6. **`Footer.tsx:152-153` states "SEVEN surfaces post at `priority:\"immediate\"`" and enumerates them.** That census is load-bearing for the fullscreen right-region rule. Task 13 makes it eight; the comment must be updated in the same commit as the poster, and the grep-count assertion added so the next poster cannot land silently.

7. **`src/appserver/schema/index.ts` is walked by the artifact generator and a drift gate.** A shipped method missing from `methodSchemas` is a build failure — and so, symmetrically, is a registered method with no handler. That is why the registration is split with its handler rather than batched: Task 10 registers `image/stage` + `turn/startContent` and regenerates `schema/json/{stable,experimental}/appserver.json` in its own commit, Task 11 does the same for `turn/steerContent`. Two `npm run emit-schema` runs, two commits, and every intermediate tree is green. All three are `experimental: true`: they ride seams (staged upload, `Query.streamInput`) with no stability promise, exactly as `turn/steer` does today.

8. **Out of scope, deliberately (spec Non-goals) — do not build:** the app-server `initialize` capability list; the fleet staging-client (F10 errors loudly instead); the opportunistic `magick`/`ffmpeg` rung; darwin `sips` unification; `ccx -p` image flags; swarm/kairos seed widening; any stranded-session recovery scan (owner fork: **fix forward only**).
