# F2 — The Keymap as Data: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use doperpowers:subagent-driven-development to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the TUI's 17 ad-hoc `useInput` callbacks with upstream's architecture: one root
raw-stdin keypress parser feeding a declarative binding table resolved over an ordered context stack,
with generic 1-second chords, `~/.claude/keybindings.json` hot reload, and every hint string derived
from the live binding.

**Architecture:** A root `KeymapProvider` consumes raw stdin bytes itself (P86b recipe: render with
`exitOnCtrlC: false`, take raw mode through `useStdin().setRawMode(true)` so Ink keeps owning termios
restore, `stdin.setEncoding("latin1")`, own `data` listener — **no `useInput` anywhere when done**),
parses bytes with our own keypress parser (P86 proved Ink's `useInput` cannot express the table:
`home ≡ end ≡ insert ≡ F1–F12`), resolves each key through swallowAll → preemptive scopes → an
ordered context stack (innermost first, `Global` last, first match wins, `null` consumes as
explicitly unbound), and dispatches matched actions to handlers components register. Unmatched
keys/text flow to the innermost fallback handler (the composer's editor), mirroring upstream's
"component code below the table" layer.

**Tech Stack:** TypeScript ESM (`.js` import specifiers), React + Ink 5.2.1, ink-testing-library,
vitest. No new runtime dependencies (file watching via `fs.watchFile` polling, not chokidar — recorded
deviation, same observable semantics: ~500 ms latency, edits apply live).

export type KeyContextName = "Global" | "Chat" | "Autocomplete" | "Confirmation" | "Help" | "Transcript"
