F. Turn queue

queueDepth —
turn idstatusposition (at announce)actions
The rows below are written only by notifications — turn/queued (the id is minted at enqueue, so it exists before the turn does), then turn/started when the drain picks it up, then turn/completed with completed/interrupted/failed/cancelled. The enqueue reply carries the identical id and is deliberately ignored here, so this panel is a real test that a second client can follow a queue it did not create: subscribe from another browser tab and you will see the same rows appear. Joining late is covered too — thread/subscribe replays one turn/queued per pending entry, FIFO.
Known wire characteristic: queueDepth travels only on the threadView projection (thread/list, thread/started) — no notification carries it, and thread/status/changed does not. The badge therefore shows the depth as of the last list, next to this console's own event-derived count; if the two disagree after a refresh, the event stream and the projection have genuinely drifted. Per-row Cancel sends turn/interrupt {turnId}, which removes just that entry and never touches the engine — the running turn keeps going.

G. Fleet adoption

The first panel here whose subject is not a thread: fleet/list reports every session on THIS MACHINE — the roster on disk joined with a live probe of each host — most of which this server has never seen. thread/attach is what turns one of those rows into a thread it holds; threadId is the one column the server itself owns, and a row that has one is a row already adopted here.

The free-text target box is not a duplicate of the row buttons. A row attaches by short, the roster's primary key, which can never be ambiguous — but the wire resolves a target as a simultaneous filter over short | sessionId | name, and two hits is an error carrying its matches (-33008 with data.matches) rather than a precedence, because a wrong guess would attach to someone else's session. Typing a shared name is the only way to reach that payload from here, so this console renders the matches as handles you can re-ask with instead of burying them in a blob.
Attach is idempotent, and its reply is what selects the thread here — deliberately, against this console's usual notification-only rule. A first attach announces thread/started to every watcher (so panel A's table fills itself), but a re-attach to a target this server already holds mints nothing and announces nothing: it just replies with the same thread. A console that selected only off the notification would silently do nothing the second time.
Stop ends the SESSION, not this server's hold on it — that is thread/close in panel A, and the two being identically shaped with opposite consequences is why stop is its own method. It answers {ok:true} only once the host's socket is at EOF and the roster row reads terminal, and thread/closed {reason:"stopped"} rides the same event. A -33008 here is that poll running out of its 10 s cap: the host would not die, and the record survives — the thread stays addressable, so nothing is dropped locally either.
No notification carries this table (the roster is disk state, not wire state): it changes when you press Refresh, and attach/stop each re-read it because they change what it says.
An attached fleet thread is not an inProcess one. The panels above will answer -33006 (unsupportedForOrigin) for the methods whose subject is an engine this server owns — the host owns a fleet thread's — and -33005 once its host dies, for everything but thread/close.

H. Workspace · files & shell

fs/search and fs/read are server-scoped like fleet/list — neither names a thread, because the subject is a path on this machine rather than a conversation, which is also why a fleet thread's tree is as readable as an inProcess one's. Root them on a thread by pasting that thread's cwd (panel A's table) as a search root. Both are unsandboxed and trusted-client, and every refusal is -32602: an fs failure is a fact about the request, not a server that broke.

path comes back root-relative with root beside it, so a match is readable without knowing which root produced it and the client does the join — which is what Read does below, textually, since this console has no path library and no idea what the server's cwd is. A trailing slash means a directory (the walker's own invariant, and the only way to tell without a field); reading one answers -32602 naming the kind, which is shown rather than pre-blocked. An empty query is a legal request with an empty answer, not a client bug, and an unwalkable root contributes nothing while the request still succeeds. Scores are comparable across roots (all ranked against the same query) and the walk is re-done every call — there is no warm index, and the cap is 50 matches.

The payload is base64 because it is BYTES: an image, a lockfile or a half-written UTF-8 sequence has to survive the trip, and a JSON string cannot carry that. So the text rendering is attempted, not assumed — a strict UTF-8 decode that throws (or a NUL byte in what decodes) falls back to hex. The note reports the reply's own size next to the decoded byte count: they can only disagree if the base64 got mangled between here and there. The server refuses above a 4 MiB read cap; the preview cap below it is this console's own and is always named when it truncates — the whole file did arrive.

Display-only — the model never sees this. That is the recorded deviation from Codex, whose thread/shellCommand streams output into the turn; ours returns it to the one client that asked and leaves the conversation untouched (the terminal's !cmd semantics). It names a thread for one reason: the thread is what knows where to run — the command lands in that thread's own cwd, the same value panel A's table shows. It is un-chained, so it runs concurrently with a turn in flight rather than queueing behind it, but it is not exempt from -33005: a thread whose engine is gone is gone for this too. Unsandboxed, like the reads above. Two timeouts stand behind it — the shared seam SIGTERMs the child at 30 s, and the handler abandons a TERM-proof child at 40 s and says so in the output rather than claiming a clean timeout, because that child may still be running.
