no rate-limit signal seen yet for the active thread
Known wire characteristic: thread/limits/updated only fires when the engine's frame carries a limit condition — there is no explicit "limit cleared" notification on this wire (routeLimits in router.ts simply never broadcasts when the classifier returns nothing). A client that merges limit state and never clears it shows a stale "rate limited" banner forever. This console auto-fades the banner once the reported resetsAt elapses (if the frame carried one) and always offers a manual Dismiss button for kinds with no resetsAt at all (usage-limit / org-policy / credits-exhausted) — it never invents a synthetic "cleared" event, it just stops trusting a stale one locally.

C. Session library

Rows include both live threads and cold (store-only) sessions this server never opened — the same merge thread/list performs server-side (sessionLib.ts). Rename/Tag/Delete/Fork address either kind by id (a bare store sessionId or a thr_… registry id both work). Resume calls thread/resume {sessionId} to bring a cold row back to life as a new live thread, reusing panel A's "start a thread" cwd/model/permission-mode/ settingSources fields as its config — the natural next action on a stored session row, and the reason this panel doesn't need its own duplicate form. Compact and Reinitialize only succeed against a live thread.
